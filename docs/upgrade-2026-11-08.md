# Project upgrade — 2026-11-08

Scope: repository-wide dependency, security, framework-compatibility and API-boundary review. This record describes local changes and checks only. It does not authorize or claim a deployment, hosted migration, billing change, or live-service validation.

## Runtime and dependencies

- Node is pinned to **24.22.2** in `.nvmrc`, `engines`, and CI (`node-version-file`). jsdom 31 requires at least Node 24.15 on the Node 24 line; the pin also makes local/CI verification reproducible.
- pnpm is pinned to **12.18.0** with its registry SHA-512 in `packageManager`.
- Direct updates: Next 16.4.5; Eve 1.0.0-rc.6; AI SDK 7.0.165; Anthropic 4.0.99; Google 4.0.114; OpenAI 4.0.111; OpenAI-compatible 3.0.87; Shiki and its three engine/core packages 4.6.0; Tailwind/PostCSS plugin 4.3.5; Supabase JS 2.119.0; Better Auth 1.7.18; docx 9.15.3; Lucide 1.70.0; Vercel Connect 2.9.0; pdfjs-dist 6.5.438; PGlite 0.5.15; jsdom 31.0.0.
- React/React DOM 19.3.1, TypeScript 7.0.2, Zod 4.6.7 and the other queried direct pins were already current. `pnpm outdated` is empty after the update.
- Existing scoped security overrides are preserved. Undici 7/8 remain separate; DOMPurify, source-map-js, KaTeX, Zod and sharp floors remain enforced. The lockfile was regenerated and the registry audit reports no known vulnerabilities. A registry audit alone does not cover vendored code or unpublished framework fixes.

## Eve rc.6 and compiled Zod

- Eve rc.6 still bundles Zod 4.5.4. The official bounded-collection fix was regenerated through `pnpm patch`/`patch-commit` for the exact rc.6 shared core `core-BBvrU4Ut.js`; the manifest, generator, audit and patch registration now name rc.6. Historical patch files remain historical artifacts and are not registered.
- `coder_patch` keeps its established tool name but now wraps rc.6 `editFile` (`path` plus unique, non-overlapping `edits`). The workspace projection invalidates cached reads for relative and workspace-absolute result paths and still understands older `apply_patch` output.
- Root `defaultTools` is explicitly false so new framework write/edit defaults cannot bypass Coder mode or approval. The existing root-copy `agent` delegation tool is re-added explicitly. Coder shell/workspace writes/patches remain mode-gated and approval-gated.
- A shell/tool result settled as `completed` with `errorText`/`error.message` or a nonzero exit code is presented as failed, not successful, in activity, chat and Coder projections.

## API and logging boundary

- `apiRoute` now preserves Next's actual handler arguments, including dynamic `{ params }`, instead of inserting wrapper metadata as the second argument.
- Every API route uses the shared boundary. Responses keep status/body/content type and multiple `Set-Cookie` values, and receive request IDs, `no-store` and `nosniff`; body-less 204/205/304 responses remain body-less. OAuth redirects and cookie handoffs are covered.
- Auth/chat failure logs use the structured redacting logger instead of raw error objects/messages. The logger's field-bearing method signatures are covered by typechecking and hostile-shape tests.

## Deployment caveat

Eve rc.6 requires a Workflow world with atomic-start support. Vercel Workflow and the local world provide it; a self-hosted Postgres world needs `@workflow/world-postgres` >= 5.1.1 and its bootstrap run before deployment. Upgrading a self-hosted/local/Postgres world can strand sessions started by the previous Eve version; history remains readable but resume behavior must be validated before rollout. This repository's Vercel integration was not deployed or migrated here.
