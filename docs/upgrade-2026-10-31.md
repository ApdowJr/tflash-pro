# Platform upgrade — 2026-10-31

This upgrade moves Tflash to the current Eve runtime (`1.0.0-rc.1`) and clears
the dependency majors that were intentionally held during the October security
pass. User-facing flows are unchanged: plan, artifact and research cards still
render, approval and question prompts keep their localized labels, and the
Stop/response recovery warnings still fail closed.

## Eve 1.0.0-rc.1 migration

The migration follows the installed `eve/docs/guides/upgrade/*` pages and the
v1 frontend reference.

### Agent runtime

- `defineDynamic` now takes one async resolver instead of per-event handlers.
  The resolver still reads the validated provider/model selection from session
  auth attributes and returns the live `LanguageModel` plus its context window.
- Compaction uses `threshold: 0.85` instead of `thresholdPercent`.
- The per-turn model-step budget listens to `model.started` and counts `runId`
  rather than `stepIndex`. A replayed run id is idempotent; distinct runs count
  toward the existing 1–30 limit (default 12).
- The self-modification extension moved to
  `eve/extensions/self-modification/local`.
- Sandbox reads use the v1 `signal` option instead of `abortSignal`.
- Web search is constructed with `webSearch({ provider: "exa" })`; unsupported
  direct providers are still not silently rerouted.
- MCP connections use the v1 `AuthorizationDefinition` /
  `ConnectionAuthResolver` types and `principalType` (`"user"`/`"app"`)
  instead of the removed credential-owner shape.

### Client and message model

- The chat uses `Client({ baseUrl })`, `useEveAgent`, `agent.view`,
  `agent.messages`, `agent.status`, `agent.error` and `resume()`.
- Rendered messages are the v1 `MessagePart[]` model: `text`, `reasoning`,
  `file`, `tool` and `interaction`. Tflash's domain cards still read the tool
  parts directly rather than replacing them with generic trace components.
- Approvals and questions are v1 interactions. `AgentInputResponse` keeps its
  exported name but now carries `interactionId`; approval option ids are
  `approve`/`deny`, and question lookup uses the interaction's call id.
- Tool parts use `callId`, `stepIndex`, `kind`, `name`, `label` and a v1
  `CallState`. Legacy activity-row states are derived from that state so the
  activity panel's contract does not change.
- Usage comes from incremental `usage.recorded` facts, deduplicated by stream
  position. Missing metrics stay unknown instead of being presented as a
  partial total.
- Task settlement comes from `task.ended` v1 facts. A replay
  cannot undo a terminal task, and a completed bash task still reads as
  `outcome-unknown` unless the command result itself proves success.

### Recovery and search

- Stop recovery clears a fixed-turn warning only on that turn's
  `turn.settled { outcome: "cancelled" }`. The v0 `turn.cancelled` +
  `session.waiting` pair is no longer used.
- Input-response recovery clears a marker only on `interaction.settled` for the
  same interaction id. Optimistic local state still does not clear it.
- Chat search parses stream version `"27"`. It ignores `$eve` transport records,
  honors a `$eve:"position"` marker before any stored line, and indexes only
  text the UI renders: user delivery text, imported history, and completed
  assistant text. Reasoning, tool output, results and file metadata are not
  searchable conversation text.
- A successful v1 cancel must be a delivery receipt
  (`{ ok: true, sessionId, deliveryId }`). Anything else is treated as a failed
  Stop response, so the reconnect path is not entered on an invalid receipt.

## Bundled-Zod security backport

Eve 1.0.0-rc.1 still bundles Zod 4.5.4, which is affected by
[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). The
pnpm override for the external `zod` package cannot replace Eve's compiled
copy, so the existing source backport was regenerated for the new shared core
chunk (`core-BsvaaMUJ.js`).

- The same six integration points are patched: three runtime collection parsers
  and three compiled emitters.
- `scripts/build-eve-zod-backport.mjs` now discovers the shared core chunk and
  refuses any Eve version/chunk whose exact original SHA-256 has not been
  reviewed.
- `patches/eve-zod-backport.json` records the new version, chunk name and
  resulting hashes. The audit and integrity tests verify bytes plus the
  array/map/set behavior probes rather than trusting a marker.
- `pnpm-workspace.yaml` registers `eve@1.0.0-rc.1` with the regenerated
  `patches/eve@1.0.0-rc.1.patch`; the lockfile pins the patch hash.

## Verification

Run with Node 24 and the pinned pnpm:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm audit:security
corepack pnpm audit:bundled-zod
corepack pnpm test
corepack pnpm typecheck
corepack pnpm build
corepack pnpm build:eve
```

Results on this change:

- `pnpm test`: 450 tests, 450 pass, 0 fail.
- `pnpm typecheck`: 0 errors.
- `pnpm build`: Next production build succeeds; all existing routes remain.
- `pnpm build:eve`: Eve/Nitro production build succeeds.
- `pnpm audit:security`: no known vulnerabilities.
- `pnpm audit:bundled-zod`: exact backport verified and all size gates pass.

## Boundaries

- Tests use mocks and local fixtures. They do not prove live provider, hosted
  Supabase, sandbox or Workflow-world behavior.
- The upgrade does not add new product behavior, permissions, billing limits or
  cross-turn replay. Recovery markers remain browser hints, not server-side
  exactly-once guarantees.
- The bundled-Zod backport makes existing leading size bounds effective early;
  it does not add bounds to unbounded schemas or replace request-size and
  deployment resource limits.
