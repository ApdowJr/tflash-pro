# Platform upgrade — 2026-10-29

This pass hardens the parts of Tflash that are not user-visible until something
goes wrong: request logging, error boundaries, security headers, abuse limits,
and the dependency floor. Feature behavior and every existing test contract are
unchanged.

## What changed

### 1. One API response vocabulary

`lib/http/api-response.ts` is now the single place that defines how a JSON
route answers: `jsonOk`, `jsonError(code, message)`, a `STATUS_FOR_CODE` table,
content-type checking, and a bounded `readJsonObject`. Every response carries
`cache-control: no-store` and `x-content-type-options: nosniff`, including error
responses that previously had no cache headers at all.

Client code can now branch on a stable `code` (`UNAUTHORIZED`, `RATE_LIMITED`,
`INTERNAL`, …) instead of parsing a human sentence.

### 2. Request ids and structured, redacting logs

`lib/http/api-route.ts` wraps a handler and provides:

- a request id, echoed as `x-request-id` (a client value is only reused when it
  is 8–64 alphanumeric characters, so it cannot inject markup),
- a hard error boundary: an unexpected throw becomes `{ ok: false, code:
  "INTERNAL" }` with a 500 and the id — never a stack trace,
- one structured log line with method, path, status and duration.

`lib/observability/logger.ts` writes JSON lines in production and readable
lines in development. Two independent protections keep credentials out of logs:

1. **Key masking** — any key matching `secret|token|password|api_key|
   authorization|cookie|credential|owner_proof|private` is replaced.
2. **Value scrubbing** — credential shapes are masked even when they appear
   inside free text: vendor prefixes (`sk-…`, `ghp_…`, `xoxb-…`, `AIza…`), JWTs,
   `Bearer …` headers, and `token=…`-style assignments (the label is kept for
   readability).

Errors are expanded to `{ name, message, code }` with causes followed one level
so a wrapped `fetch` failure is still diagnosable. `TFLASH_LOG_LEVEL` sets the
threshold; the default is `info` in production and `debug` elsewhere.

Applied to: `health`, `providers/test`, `providers/connect`, `documents/read`,
`documents/export`, `integrations/connect`.

### 3. Rate limits where cost is external

`lib/security/rate-limit.ts` is a fixed-window counter with an injectable clock;
`lib/security/rate-limits.ts` names the buckets:

| Bucket | Limit |
| --- | --- |
| provider test | 20 / min |
| provider connect | 30 / min |
| provider models | 60 / min |
| integration connect | 30 / min |
| document read/export | 30 / min |
| chat creation | 30 / min |

A limited request gets `429` with `retry-after` and `x-ratelimit-*` headers.

**Honest scope:** this lives in one Node process. On serverless, each instance
keeps its own window, so it blunts retry storms and casual abuse but is not a
distributed quota and must not be used for billing or per-account legal limits.
A platform-level limiter or WAF is still required in front of production.

### 4. Error boundaries and last-resort UI

- `app/error.tsx` — route boundary with the error digest, Retry and New chat.
- `app/global-error.tsx` — replaces the root layout, so it ships its own inline
  styles and does not assume the stylesheet loaded.
- `app/not-found.tsx` — the 404 surface.
- `components/app/error-state.tsx` — one shared, server-safe, bilingual view.

Copy is bilingual rather than language-detected: an error is the worst moment
to guess from a cookie that may be the thing that failed.

### 5. Connection awareness

`components/app/connectivity-banner.tsx` shows an offline banner on
`navigator.onLine === false` and a short "back online" confirmation, announced
through `role="status"`. It deliberately says the *device* is offline; it does
not claim the server, database or model provider is reachable.

### 6. Security headers

`next.config.ts` now sends `X-Content-Type-Options`, `Referrer-Policy`,
`X-DNS-Prefetch-Control: off`, a `Permissions-Policy` that grants the microphone
to this origin only (voice input) and denies camera, geolocation, payment, USB
and display capture, `Cross-Origin-Opener-Policy: same-origin-allow-popups` (so
OAuth consent popups still work), and HSTS. `poweredByHeader` is off and
`reactStrictMode` is on.

**Deliberately not set:** `X-Frame-Options` / `frame-ancestors`, because the app
is embedded in the preview iframe of its host and any fixed ancestor list breaks
that; and `Content-Security-Policy`, because a correct policy needs per-request
nonces plus an audit of every remote origin, and a loose one would be worse than
none. Both remain tracked work.

### 7. Metadata and installability

`app/manifest.ts` and `app/robots.ts` were added. The manifest makes the app
installable without registering a service worker, so no conversation data is
cached on a shared device. Robots disallows `/`, `/s/`, `/api/`, `/auth/` and
`/eve/` — chat transcripts are private and require an authenticated owner.

### 8. Smaller user-visible improvements

- The browser tab now names the open conversation
  (`Title · Tflash`), truncated at 72 characters, instead of always saying
  "Tflash".
- Shiki (grammar engine + themes) is now loaded on demand by
  `components/ai-elements/code-block.tsx` instead of being part of the chat
  route's first load. Failed loads no longer poison the per-language cache.

## Dependencies

Minor/patch updates, all validated by the full suite and a production build:
`@ai-sdk/anthropic` 4.0.92, `@ai-sdk/google` 4.0.108, `@ai-sdk/openai` 4.0.105,
`@ai-sdk/openai-compatible` 3.0.81, `ai` 7.0.157, `react`/`react-dom` 19.3.1,
`@types/react`/`@types/react-dom` 19.3.0, `radix-ui` 1.8.1,
`@radix-ui/react-use-controllable-state` 1.3.0, `lucide-react` 1.64.0,
`streamdown` 2.7.1, `@streamdown/{cjk,math,mermaid}` 1.0.4/1.0.3/1.0.3,
`tailwindcss`/`@tailwindcss/postcss` 4.3.3, `tailwind-merge` 3.7.0,
`use-stick-to-bottom` 1.1.6, `@opentelemetry/api` 1.10.0.

Majors were held on purpose:

- **eve 0.83.2** — pinned, with the version-pinned Zod backport described in
  [dependency security](dependency-security.md). Upgrading it is its own change
  with its own gate.
- **shiki 4 / `@streamdown/code` 2** — the code-block integration needs a
  migration review, not a version bump.
- **motion 14, `@vercel/connect` 2, `@types/node` 26, nanoid 6, typescript 7** —
  no security driver; changing them would mix an API migration into a hardening
  pass.

`pnpm audit --audit-level=low` reports no advisories and the bundled-Zod gate
still verifies the patched Eve chunk hashes.

## Validation

```bash
corepack pnpm test        # 180 tests (10 new in tests/platform-upgrade.test.mjs)
corepack pnpm typecheck
corepack pnpm build       # includes /robots.txt and /manifest.webmanifest
corepack pnpm audit:security
corepack pnpm audit:bundled-zod
```

New tests cover: key/value redaction including malicious message text, cycle and
non-serializable handling, request-id generation and rejection, cache headers on
success and error, bounded JSON parsing, the route wrapper's 500 boundary and id
echo, and the rate limiter's window/expiry/key derivation and 429 metadata.

A local `next dev` run was verified for `/login` (200), an unknown path (404 with
the new page), `/robots.txt`, `/manifest.webmanifest`, `/api/health`, and the
presence of the new security headers. This does **not** establish live provider,
Supabase, Eve sandbox or production readiness.

## Local runtime note

Eve requires Node.js ≥ 24 and refuses to start on 22. The repository already
declares `"node": "24.x"`; the dev container used for this pass needed a Node 24
binary added to `PATH` before `pnpm dev` would boot. CI already pins Node 24.
